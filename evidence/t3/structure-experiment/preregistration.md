# 预登记：`structure` 维度「散文口径 vs 机械口径」控制实验

- **登记时间**：2026-09-27，随 commit 1（R1–R6）提交，**早于实验运行**。
- **状态**：预登记文件本身不产生任何实验数据；跑完的原始记录在 `evidence/t3/structure-experiment/`。
- **判据的机器可读副本**：同目录 `criteria.json`，实验脚本**读它**来判成败，不把判据写死在代码里。

## 为什么做这个实验

T3 的简版 Prompt 入口实测里，`structure` 维度连续 3 次写出「省略号拼接」的引用（散文口径下），
换成「按句切开、整句复制」的机械操作法后一次成功。但这是 **n=1**，
而且机械做法带一条回退（找不到完整句子 → 判「无法判断」），
**可能改变档位输出**——中文口头作答常常整段没有句号，那正是目标用户最典型的状态。

所以：这是一次**尺子候选**，不是一次文案润色。要动 `rules`，必须先过这个实验。

## 设计（预先写死，跑完不改）

| 项 | 值 |
| --- | --- |
| 批次 | 6 个案例：`C01`、`C05`、`C09`、`C17`、`C21`，外加 **`C13-oral`** |
| `C13-oral` 定义 | 把 `cases.json#C13` 的首答里所有 `。` 与 `？` 替换为 `，`，**其余字符一字不动**（确定性变换，可复算）。目的是满足「批次里至少 1 个整段无句号的口语化首答」 |
| 两个版本 | `prose` = `rules@0.2.0` 正文里的散文口径（＝当前仓库 `prompts.ts` 默认渲染，逐字未改）<br>`mechanical` = 入口级操作提示 `ENTRY_HINTS.structureQuoteProcedure`（**不在 `rulesDigest` 覆盖内**） |
| 每格次数 | 3 次真实调用 |
| 总调用数 | 6 案例 × 2 版本 × 3 次 = **36 次** |
| 两版差异 | 只差 `structure` 那一条 bullet；「引用必须连续逐字、禁止省略号拼接」等真实性约束**一字未动** |
| 模型 | `qwen3.8-flash`，`enable_thinking: false`，JSON mode，`temperature 0.2`，`maxRetries 2`（与 T2 标定完全一致） |
| 配对方式 | 同一批案例、同一顺序、同一参数，两版**配对比较** |
| 复核口径 | 引用是否可定位一律用仓库自己的 `locateQuote` 独立重算，不采信模型自报区间 |

## 预登记判据（两条都满足才算「通过」，才建议升版）

1. **引用可定位率不下降**：`rate(mechanical) >= rate(prose)`
   - `rate = 全部三档维度的引用中，locateQuote 定位成功的条数 / 总条数`
2. **`structure` 的「无法判断」比例不上升**：`undetermined(mechanical) <= undetermined(prose)`
   - 这一条专门防「机械做法在无句号口语上退化成无法判断」这个已知风险
   - `undetermined = structure 维度判「无法判断」的次数 / 总轮次`

**辅助指标（只报数，不参与判定）**：首次通过率、降级数、单次延迟、总 tokens、`structure` 引用可定位率。

## 决策规则（也预先写死）

- 两条判据**都满足** → 实验结论写「通过，建议升 `rules@0.2.1`」；
  但**本轮不升版**（升版要动三个入口＋网页提示词＋重跑 `rules:write`，并交 T4 复测一轮），由 lead 决定。
- **任一不满足** → 结论写「不通过」，机械口径维持「入口级操作提示」地位，不动 `rules`。
- **无论成败，两版数字都全量报出**；不挑样本、不因为结论不好看而少报一轮。
- 若出现调用异常（HTTP 错误／超时），异常计入该版分母并如实标注，不静默丢弃。

## 这个实验**不能**证明什么

- 6 个案例、每格 3 次，样本量只够做配对方向判断，**不足以给出精确比例**；
  单格点值不可外推（T2 两轮标定的波动已经说明过一次）。
- 用的是同一台机器、同一天、同一条网络；模型侧随机性未做多次重复消除。
- 只测 `structure` 一维的操作法差异，不代表其它维度用机械做法也会更好。
