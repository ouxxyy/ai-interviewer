## 1. Skill 入口

```
skills/ai-interviewer/
```

`SKILL.md` 里的：能力边界声明、六步流程、五维定义表、`contract@0.2.0` 的 Feedback JSON 模板、

版本戳写到文件头。

### 1.2 真实调用证据

`node dist/src/t3/cli.js skill:run`（案例 `C13`，社招／产品运营，合成材料）：

| 轮 | 步骤 | 延迟 | tokens |
| --- | --- | --- | --- |
| 1 | 问题计划 | 5,406 ms | 1,153 |
| 2 | 追问判定 q1（`need=true`，针对「转化率 2.1%→2.8% 的统计口径与样本量」） | 2,483 ms | 812 |
| 3 | 五维反馈 q1（一次通过） | 8,551 ms | 2,489 |

| 7 | 全场报告 | 5,422 ms | 1,346 |

- **引用自检**：q1 `5/5` 可定位、q2 `5/5` 可定位（独立重算，非采信流水线）。
- 本次跑的是「用户提前结束」路径（完成 2 题 / 未完成 1 题），顺带验证 D6 边界：
  报告里如实写「完成 2 题 / 未完成 1 题（用户提前结束）」。
- **边界**：`skill:run` 是**用仓库流水线复现 Skill 的流程**（同一套 `prompts@0.2.0` 与定位器），
  不是「Codex/Claude Code 逐字执行 SKILL.md」。后者由 §3 的宿主实测覆盖。

## 2. 简版 Prompt 入口

### 2.1 自包含

`prompt/ai-interviewer-prompt.md`：使用说明 ＋ 完整提示词正文 ＋ **附录：完整规则正文**（内嵌）。
整段复制进普通聊天对话即可用，不读仓库、不依赖任何隐藏规则。测试里有一条断言：
使用说明部分**不得**出现 `src/rules/rules.ts`、`docs/rules.md` 这类仓库路径。

### 2.2 一题完整闭环实测

宿主：**百炼 chat completions 多轮对话**（`qwen3.8-flash`）。这是「粘贴进普通聊天」在 API 层的
等价物：同一份粘贴文本、随后全是 user/assistant 轮次、宿主拿不到仓库内容。
**第三方聊天 UI（ChatGPT／Claude 网页）未实测**，见 §5。

6 轮、10,004 tokens，闭环四项判定全 true：

| 判定 | 结果 | 怎么判的 |
| --- | --- | --- |
| 先要材料 | ✅ | 第一条回复里出现 JD／经历的索取与确认 |
| 出了题 | ✅ | 出现问句，且给出 3 道主问题与 sourceExcerpt／intent |
| 给了反馈 | ✅ | 最后一条含五维键名 |
| 五维齐全 | ✅ | 五个维度键都在 |
| **引用逐字** | ✅ **5/5** | 逐维把 `quote.text` 拿回回答原文做字符串查找 |

### 2.3 一条真实发现：`structure` 维度的引用要靠「机械做法」而不是「散文规则」

这是本轮 C 入口最有价值的产出。实测序列（每次都是真实调用）：

| 尝试 | 提示词里关于引用的写法 | 逐维引用结果 |
| --- | --- | --- |
| 1 | 「必须是连续片段；禁止省略号拼接」 | **4/5**——`specificity` 用了省略号拼接 |
| 2 | 追加 ❌ 反例 ＋「输出前逐维做字符串查找」自检 | **4/5**——`structure` 用了省略号拼接 |
| 3 | 再追加 `structure` 维度的散文式提醒（「只取一段连续原话，短一点也行」） | **4/5**——`structure` 仍然拼接 |
| 4 | **改成机械做法**：「把回答按句号切开，挑**完整的一句**整句复制」 | **5/5** ✅ |

**结论**：对 `structure` 这种天然横跨整段的维度，散文式规则（无论写得多细、带不带反例）
挡不住省略号拼接；**把动作改成机械步骤**（切句 → 整句复制）当场解决。
机械做法不仅没放宽真实性，反而更严——整句复制在构造上就是逐字的。

这条已写进两个入口的规则文案（Skill 与 Prompt 都有），并且是**同一份规则源**渲染出来的。

> 为什么值得单独记：简版 Prompt **没有引用校验回环**——粘贴进普通聊天后没有定位器兜底，
> 不合格引用会直接到达用户。所以这里的提示词质量比仓库流水线更关键。

## 4. 三入口规则不抄成三份（A8 的地基）

- **唯一源**：`src/rules/rules.ts`（`rules@0.2.0`）。
- **生成**：`docs/rules.md`、`skills/ai-interviewer/references/rules.md`、简版 Prompt 的规则附录，
  以及提示词里的共同红线——全部由同一组常量渲染。
- **机器检查**（每次 `npm test` 都跑）：
  - 三个生成物与生成器输出**逐字一致**（手改产物、或改了规则源忘了重跑，测试直接红）；
  - 两个 T3 入口都带 `rules@0.2.0` 与**完整** `rulesDigest()`（sha256）——
    外部只要对规则正文跑一次 `shasum`，就能核对「三个入口是不是同一份规则」；
  - 简版 Prompt 内嵌的 JSON 模板必须过 `feedback` Schema。

**A8 一致性验收本身仍未做**——它要求三个入口对同一组案例给出可比对的事实缺口与引用判断，
而网页入口还没开工。本轮只保证**地基**（单源 + 版本号 + 摘要 + 生成物一致性）成立。

  我这里有现成的对照数据（散文 3 次失败 vs 机械 1 次通过，`evidence/t3/prompt/`）。
