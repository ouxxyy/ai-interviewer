## 2. 简版 Prompt 入口

### 2.1 自包含

`prompt/ai-interviewer-prompt.md`：使用说明 ＋ 完整提示词正文 ＋ **附录：完整规则正文**（内嵌）。
整段复制进普通聊天对话即可用，不读仓库、不依赖任何隐藏规则。测试里有一条断言：
使用说明部分**不得**出现 `src/rules/rules.ts`、`docs/rules.md` 这类仓库路径。

### 2.2 一题完整闭环实测

宿主：**百炼 chat completions 多轮对话**（`qwen3.8-flash`）。这是「粘贴进普通聊天」在 API 层的
等价物：同一份粘贴文本、随后全是 user/assistant 轮次、宿主拿不到仓库内容。
**第三方聊天 UI（ChatGPT／Claude 网页）未实测**，见 §5。

6 轮、10,004 tokens，闭环五项判定全 true：

| 判定 | 结果 | 怎么判的 |
| --- | --- | --- |
| 先要材料 | ✅ | 第一条回复里出现 JD／经历的索取与确认 |
| 出了题 | ✅ | 出现问句，且给出 3 道主问题与 sourceExcerpt／intent |
| 给了反馈 | ✅ | 最后一条含五维键名 |
| 五维齐全 | ✅ | 五个维度键都在 |
| **引用可定位** | ✅ **5/5** | **契约口径**：逐维把 `quote.text` 交给仓库的 `locateQuote`，记录它算出的区间 |

> **R1 订正（口径）**：这项原先用的是 `String.includes`（子串包含），比契约松，而且 `quoteChecks` 里
> 根本没有区间字段——模型自报的 `start`/`end`（5/5 与定位器实算不符）被如实录进了 transcript，
> 却没有任何东西校验它们。现在改成：**判据 = `locateQuote`**，区间由定位器**权威回写**
> （模型自报区间一律不采信），`quoteChecks` 只记定位器算出的 `start`/`end`/`matchType`。
> 这是 `docs/contracts.md` 第 5 条「应用层权威重定位」在聊天入口上的落地。

### 2.3 一条真实发现：`structure` 维度的引用要靠「机械做法」而不是「散文规则」

这是本轮 C 入口最有价值的产出。实测序列（每次都是真实调用）：

| 尝试 | 提示词里关于引用的写法 | 逐维引用结果 |
| --- | --- | --- |
| 1 | 「必须是连续片段；禁止省略号拼接」 | **4/5**——`specificity` 用了省略号拼接 |
| 2 | 追加 ❌ 反例 ＋「输出前逐维做字符串查找」自检 | **4/5**——`structure` 用了省略号拼接 |
| 3 | 再追加 `structure` 维度的散文式提醒（「只取一段连续原话，短一点也行」） | **4/5**——`structure` 仍然拼接 |
| 4 | **改成机械做法**：「把回答按句号切开，挑**完整的一句**整句复制」 | **5/5** ✅ |

**结论**：对 `structure` 这种天然横跨整段的维度，散文式规则（无论写得多细、带不带反例）
挡不住省略号拼接；**把动作改成机械步骤**（切句 → 整句复制）当场解决。
机械做法不仅没放宽真实性，反而更严——整句复制在构造上就是逐字的。

这条已写进两个入口的规则文案（Skill 与 Prompt 都有），并且是**同一份规则源**渲染出来的。

> 为什么值得单独记：简版 Prompt **没有引用校验回环**——粘贴进普通聊天后没有定位器兜底，
> 不合格引用会直接到达用户。所以这里的提示词质量比仓库流水线更关键。

## 3. 宿主实测（issue §7 要求「Codex 与 Claude Code 各实测一次」）

结论**从原始终端输出里算出来**，不是手写断言（`src/t3/hosts.ts` 做字符串匹配）。

**R5 订正（判据范围）**：判据只扫**宿主自己的最终回答块**（最后一次 `tokens used` 之后那 93 个字符），
要求「块内至少命中一条能力边界短语」**且**「块内出现规则版本号」。
原先的实现是**全文扫描 + 阈值 ≥1**，会把宿主**回显的 SKILL.md 正文**误当成宿主自己的声明——
「没有实时语音」这句在原始输出里只出现在第 77 行那份被回显的文档里（行首 `> `），
宿主自己的回答块写的是「没有录音**和**实时语音能力」，字符串上并不含「没有实时语音」。
现在 `summary.json` 的 `matchedPhrases` 只反映块内命中（实测 3 条：
「没有录音」「不能听也不能说」「仅支持纯文字」），
并把只出现在回显文档里的短语单列到 `matchedPhrasesOutsideAnswerBlock`（实测：`["没有实时语音"]`）。
**结论不变**（块内确有边界声明 ＋ `rules@0.2.0`），但它现在不再依赖一个分不清「自己说的」和「回显的文档」的检查。

**另一处如实说明**：`recordHosts()` 在脱敏生效时会**就地重写** `codex-raw.txt`
（家目录前缀 `/Users/<name>` → `~`）。所以入库的是**脱敏后**的字节，manifest 里的 sha256 也是脱敏后的；
复核者拿不到脱敏前的原文。脱敏规则与被改写的字段在 `src/t3/hosts.ts`，脱敏前后行数不变。

| 宿主 | 状态 | 依据 |
| --- | --- | --- |
| **Codex CLI** | ✅ **verified** | `codex exec --skip-git-repo-check` 真跑，Skill 从 `<项目>/.codex/skills/` 被加载；输出里同时命中能力边界短语（「没有录音」「没有实时语音」「不能听也不能说」「仅支持纯文字」）与 `rules@0.2.0`。原始输出（家目录前缀已脱敏为 `~`）见 `evidence/t3/hosts/codex-raw.txt` |

## 4. 三入口规则不抄成三份（A8 的地基）

- **唯一源**：`src/rules/rules.ts`（`rules@0.2.0`）。
- **生成**：`docs/rules.md`、`skills/ai-interviewer/references/rules.md`、简版 Prompt 的规则附录，
  以及提示词里的共同红线——全部由同一组常量渲染。
- **机器检查**（每次 `npm test` 都跑）：
  - 三个生成物与生成器输出**逐字一致**（手改产物、或改了规则源忘了重跑，测试直接红）；
  - 两个 T3 入口都带 `rules@0.2.0` 与**完整** `rulesDigest()`（sha256）——
    外部只要对规则正文跑一次 `shasum`，就能核对「三个入口是不是同一份规则」；
  - 简版 Prompt 内嵌的 JSON 模板必须过 `feedback` Schema。

**A8 一致性验收本身仍未做**——它要求三个入口对同一组案例给出可比对的事实缺口与引用判断，
而网页入口还没开工。本轮只保证**地基**（单源 + 版本号 + 摘要 + 生成物一致性）成立。

## 6. 控制实验：`structure` 散文口径 vs 机械口径（预登记）

**预登记先于运行**：`evidence/t3/structure-experiment/preregistration.md` ＋ `criteria.json`
（机器可读判据，脚本读它判成败）在 **commit 1（`38a77e4`）** 就落盘，实验在 **commit 2** 才跑。
判据没改过。

**设计**：6 案例 × 2 版本 × 3 次 = **36 次真实调用**（实测 36 次、88,129 tokens、`qwen3.8-flash`）。
批次含 `C13-oral`（把 C13 首答的 `。`／`？` 全换成 `，`，其余一字不动），专门覆盖
「中文口头作答整段没句号」这个回退风险。两版差异**只有 `structure` 那一条 bullet**，
真实性约束一字未动（有单测断言）。

**结果（两版数字全量报出）**：

| 指标 | 散文版 | 机械版 | 判定 |
| --- | --- | --- | --- |
| 引用可定位（判据 1） | **86/86 = 100%** | **87/87 = 100%** | `mechanical >= prose` ✅ |
| `structure` 判「无法判断」（判据 2） | **0/18 = 0%** | **0/18 = 0%** | `mechanical <= prose` ✅ |
| 首次通过 | 18/18 | 18/18 | 辅助 |
| 降级 | 0 | 0 | 辅助 |
| `structure` 引用可定位 | 100% | 100% | 辅助 |
| 单次 P50 | 9,524 ms | 10,635 ms | 辅助 |
| tokens | 43,848 | 44,281 | 辅助 |

**按预登记判据：两条都满足，实验「通过」。** 但**这个「通过」必须配合下面三条一起读**，
否则会被误读成「机械版更好」：

1. **两版都撞了天花板，实验证明的是「不更差」，不是「更好」。** 18 轮里两版都是零重试、
   引用 100% 可定位、`structure` 零「无法判断」。判据本身是**非劣**设计（`>=` / `<=`），
   在同为满分时它只能排除「机械版明显更糟」，**不能**给出机械版更优的证据。
2. **更要紧的：这个实验没有复现出当初的动机现象。** 触发这次讨论的是
   「`structure` 连续 3 次写出省略号拼接稿」——但那 3 次发生在**简版 Prompt 入口**
   （粘贴进聊天宿主，**没有校验回环**）。本实验走的是 `runReview` 流水线，它带 2 次重试 ＋
   针对性整改，**把这类失败吸收掉了**：散文版在这个流水线里 18/18 一次通过。
   所以实验回答的是「在**有重试**的流水线里两版有没有差别」，而不是「在没有回环的入口里」。
   动机场景没有被复制过来，这是设计上的缺口，我如实标出来。
3. **预登记要防的那个具体风险没有出现**：`C13-oral`（整段无句号）在两版下都是
   `structure = 充分清楚`、5/5 引用可定位。机械做法的回退（找不到完整句子 → 无法判断）
   在这批语料上**没有触发**——因为这种口语稿按 `。／？／！` 切完就是一整段，
   「整句复制」退化成「整段复制」，仍然逐字。这是本次实验最有用的一条**否定结果**：
   风险比预想的小，但样本只有 1 个口语案例 × 3 次。

**我的读法（供 lead 决策，不代替决策）**：按预登记的决策规则，通过 → 可建议升 `rules@0.2.1`。
但实验**没有区分度**，我**不建议**仅凭它就动尺子；维持「入口级操作提示」的现状成本更低、
且已经用 `ENTRY_HINTS` 常量锁住了单源。真要转正，应该先补一个**能复现动机场景**的实验
（在**无重试**条件下比两版，或直接测聊天宿主），而不是拿这次的结果去升版。

**未做到**：① 没有在无重试条件下比较（因此动机现象未复现）；② 口语化样本只有 1 个案例 ×3 次；
③ 单格点值不可外推（与 T2 §3 同一口径）；④ 结果拿回来后我没有动任何版本号。
