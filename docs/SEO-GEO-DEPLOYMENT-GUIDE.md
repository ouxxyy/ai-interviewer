# 双站 SEO / GEO 发布与验收

本仓库内容与打包步骤必须以当前源码为准，不能直接重放历史部署包。

## 发布范围

个人主页的 `site/` 为唯一静态部署源，运行 `python3 scripts/build_seo_geo.py` 生成检索文件、部署 ZIP 与 SHA-256 清单。保留首页介绍、价格、联系方式、公众号领取文案及统计。

面试项目先运行 `python3 scripts/build-seo-geo.py`，再运行 `npm run build`。保留首次百炼配置引导、既有埋点及会话/数据逻辑。岗位页面使用稳定的 `/roles/styles.css`，不得绑定某次构建的哈希 CSS 文件。

## 部署

1. 通过既有宝塔界面确认当前站点根目录及服务实际目录；核对正在部署的源码与发布产物摘要。
2. 备份目录放在公开站点之外，保留旧源码、入口、静态资源、此次变更清单和回滚脚本。
3. 排除凭据、数据库、录音、用户上传、测试数据与本地历史目录。先在独立暂存目录解包/构建/验证，再切换入口，保留旧哈希资源。
4. 面试后端静态托管修改需要重启现有 `ai-interviewer.service`。保留原服务配置、环境文件、用户数据和凭证主密钥，禁止整体覆盖应用目录。
5. 源码与实际发布产物保持一致，避免后续构建覆盖这次改动。

## 验收

- 对两个 sitemap 中的每个公开 URL 检查 GET 和 HEAD、MIME、正文、唯一 H1、canonical、Schema JSON 与所有本地资源引用。
- robots/llms 必须是实际纯文本，sitemap 必须是 XML；返回首页 HTML 的 200 不能算这些文件存在。
- FAQ 结构化数据必须与可阅读的正文一致。面试首页启用 JavaScript 后仍保留公开练习库和 FAQ 入口。
- 新访客仍先配置百炼；已有配置不丢失；API 隔离、私有页面 noindex、未知资源 404、路径越界拒绝保持正常。
- 实际运行三个自测工具，包括空输入、未勾选、词表不适配、正常结果、复制失败和成功；示例不作为真实经历或效果证据。
- 在既有统计后台或数据层确认目标站点的页面访问与成功事件，区分测试标记和真实流量。只出现脚本或 HTTP 200 不能代替事件入库证明。
- 保存桌面/移动截图及结果；真实手机、真实语音、付费模型和收录/排名情况按实际执行范围记录，不填造通过。

部署可用、搜索引擎收录、AI 推荐和业务增长是不同结论。发布后应按固定查询与同口径时间窗口继续观察，不能用上线成功代替 SEO/GEO 效果。
