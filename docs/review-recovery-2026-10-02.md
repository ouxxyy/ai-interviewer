# 评审失败恢复与免费验收（2026-10-02）

## 结论

本地修复及免费验证通过：`npm test` 294/294、正式 Chrome 替身检查 27/27。本轮真实 API 调用为 0，公网未发布、未 push，现有用户数据与配置未改。

原故障只能确认两次评审尝试未成功、最终为 schema_error；旧记录没有具体字段诊断，不能把此次合成回归发现的坐标问题断言为原故障的唯一根因。

## 修改

- 评审先检查 JSON 根类型；null、数组、数字、字符串按结构失败重试/降级，不再在写元数据时抛异常。
- 对本题轮次且能精确/规则归一定位的原话，先回填应用计算的坐标、匹配类型和文本版本，再过完整 Schema。解决坐标缺失/类型错误使应用来不及重定位就拒绝点评的问题。模型负责的原话、轮次身份、等级、理由、缺口和建议不补写，未知字段不删除，原引用定位标准不变。
- 每次尝试提供固定字段路径与规则码，例如 `/nextFacts: required`。网页保存 attemptLog 并写安全诊断日志；不存原始模型响应、回答、解析片段或未知属性名。旧记录可缺省此字段；不迁移正式契约或 SQLite。
- 新增 `POST /api/sessions/:sid/review/retry`：只允许当前失败评审，使用相同已确认回答，不重录、不增加轮次、不消耗一次重答额度。已有有效点评、正在运行的并发请求、无失败上下文和额度止损均拒绝。每次显式操作仍最多两次评审尝试，不新增后台重试循环。
- 重答评审失败时不再额外请求重答对比；成功重试后继续原有对比流程。
- 页面将失败显示为系统状态，说明原因、尝试次数、回答仍保留和重新调用费用；提供“重新评审”。不把“无新增事实要求”当建议，不显示“点评已就绪”，降级结果不作为“最近完成”的点评。成功后恢复正常点评和完成计数，报告按各题最新评审状态标记降级。
- 契约 `0.3.0`、规则 `rules@0.3.0`、模型提示词 `prompts@0.3.2` 均不变。共享验证器新增可选诊断字段引起 TypeScript 联合数组推导差异，T3 的错误筛选改为展开数组后过滤，运行语义不变。
